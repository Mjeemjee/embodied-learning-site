前置 0.1 什么是代码？编程是什么？

很多人觉得编程很神秘。其实代码就是「写给电脑的说明书」——你告诉电脑做什么，它照做，做完把结果告诉你。

🌼 生活类比：给室友留便条

你在冰箱上贴便条：「冰箱里有蛋糕，饿了就吃一块」。这就是一条指令。代码也一样——只是你把指令写进一个文件，电脑（Python）一行行读、一行行执行。

你的第一行代码

页面支持运行本课固定示例。复制后也可在 Python 中练习；完整项目请使用本地 Python 环境。

下面这个叫 Hello World——全世界程序员的第一课。点「运行看看」，看代码怎么"说话"：

📄 hello.py
# 这是我的第一行代码！
# 井号 # 开头的是"注释"——电脑会跳过，不执行

print("Hello World！你好，世界！")
print("1 + 2 =", 1 + 2)

# 变量 = 贴了标签的盒子，可以放东西
名字 = "小明"
年龄 = 10
print("我叫", 名字, "，今年", 年龄, "岁")

# 还可以改里面的东西
年龄 = 11
print("过了一年，我", 年龄, "岁了")

三个最重要的概念

① 变量 = 贴了标签的盒子：x = 5 意思是"拿一个盒子，贴上标签 x，里面放数字 5"。

② 函数 = 一个可重复使用的步骤：print() 就是函数——它的工作是"把括号里的东西显示在屏幕上"。

③ 注释 = 写给人类看的：# 开头那一行，电脑当没看见，方便你以后回来看懂。

💡 记住一件事就够了：编程不是背诵，而是「我想让电脑做什么 → 用代码写出来 → 跑一下看看」。刚开始写错很正常，每个程序员都是这么过来的。

前置 0.2 什么是人工智能（AI）？

人工智能研究如何让计算机完成感知、推理和决策等任务。本课程先从机器学习入门：让计算机从数据里学习规律。

🌼 识别猫和狗

传统编程：你写几百条规则——「耳朵尖的是猫、耳朵圆的是狗、鼻子黑的……」——永远写不完。
机器学习（AI）：你给电脑看 10000 张猫的照片和 10000 张狗的照片，它自己找出区别。你写的代码只有几行，剩下的交给数据。

AI 不是魔法——三步拆解

① 准备数据：收集「输入 → 正确答案」的例子（猫照片 → 猫、狗照片 → 狗）

② 训练模型：让电脑对着数据一遍遍练习，自己调整内部参数

③ 推理预测：训练好后，给它一张新照片，它说出是猫还是狗

📄 理解 AI 的思路
# AI 学习的核心思路

# 第1步：创建一个空模型（参数随机）
print("第1步: 创建空白大脑")

# 第2步：喂数据训练
print("第2步: 用 10000 个例子训练")
训练次数 = 5
for i in range(训练次数):
    正确率 = 20 + i * 15
    print("  第", i+1, "轮训练, 正确率:", 正确率, "%")

# 第3步：推理
print("第3步: 输入一张新图片")
print("  模型输出: 0.97 概率是猫")
💡 记住：AI 不是「发明了新规则」，而是「从例子里学到了规律」。就像你小时候看多了猫，自然就知道长什么样的动物叫猫，不需要别人一条条教你「耳朵要尖、胡子要长」。

③ 条件判断：让代码学会「如果…就…」

📄 条件判断

    print("太远了，前进")

④ 函数：打包一段代码，随时调用

📄 定义函数
# def 定义函数 = 给一段代码起名字

前置 0.4 数组与矩阵启蒙 · 用代码做数学

机械臂动起来，靠的是数学——关节怎么转、手到哪了，全都用矩阵（数字表格）算出来的。这节先用 Python 列表理解数组与矩阵；NumPy 是以后高效完成这些运算的工具。

🌼 不需要懂大学数学

你暂时只需要知道三样东西：
① 数组（array） = 一行数字，代表"关节角度"或"坐标位置"
② 矩阵乘法 = 把数字按规则乘起来，把"旋转"和"平移"合成一步
③ NumPy = 帮你快速计算这些的工具，不用自己写循环

① 创建数组：一行数字的容器

📄 创建数组
# 数组 = 一行数字
关节角度 = [30, 45, 60]
位置坐标 = [10, 20, 5]

print("关节角度:", 关节角度)
print("位置坐标:", 位置坐标)

# 数组加减：对应位置相加减
新角度 = [关节角度[0]+5, 关节角度[1]+5, 关节角度[2]+5]
print("每个关节+5度:", 新角度)

# 数组乘法：每个元素乘以同一个数
角度翻倍 = [关节角度[0]*2, 关节角度[1]*2, 关节角度[2]*2]
print("角度翻倍:", 角度翻倍)

② 二维数组：像 Excel 表格一样

📄 二维数组（矩阵）
# 矩阵 = 二维数组 = 有行有列的数字表格
矩阵 = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]

print("这是一个 3x3 矩阵:")
for 行 in 矩阵:
    print(行)

# 取第 1 行第 2 列（从 0 开始数！）
print("第1行第2列:", 矩阵[0][1])
print("第2行:", 矩阵[1])

③ 矩阵乘法的直观理解

📄 矩阵乘法（简化）
# 旋转矩阵 x 位置向量 = 旋转后的新位置
# 这是机械臂运动学的核心！

旋转 = [[0, -1], [1, 0]]
位置 = [3, 1]

新x = 旋转[0][0]*位置[0] + 旋转[0][1]*位置[1]
新y = 旋转[1][0]*位置[0] + 旋转[1][1]*位置[1]

print("原始位置: (", 位置[0], ",", 位置[1], ")")
print("旋转90度后: (", 新x, ",", 新y, ")")
print("(3,1) 逆时针转90度 变成 (-1,3)")
💡 这一节的底线：你不需要现在就完全理解矩阵乘法。只需记住——机械臂的每个关节旋转，在数学上都等于「用一张数字表格去乘坐标」。后面学坐标变换时会用模拟器直观演示。

第 1 节 什么是具身智能？

先别被"具身"吓到。它拆开就是两个词：

  • 具身（Embodied）：有"身体"的
  • 智能（Intelligence）：会思考、会学习

合起来就是：让一个有机器"身体"的家伙去感知世界、做出动作，而不是只在电脑里打字。

🌼 最简单的例子：让机器人帮你拿水杯
  1. 📷 看（感知）：摄像头拍到你桌上的水杯在哪
  2. 🧠 想（决策）：判断位置 → 计算机械臂怎么伸过去、用多大力
  3. ✋ 动（行动）：驱动电机转动关节，抓住水杯递给你
🔄 完整闭环

看 → 想 → 动 不是一次性的，而是不断循环。发现水杯滑了？立刻调整力气。这叫"感知-决策-执行"闭环。

和普通 AI（比如聊天机器人）有什么不同？

普通 AI：输入文字 → 输出文字。它活在屏幕里，不会影响真实世界。

具身智能：输入传感器数据（摄像头、力传感器）→ 输出真实动作（转动关节、抓取）。它会改变物理世界，而且动作做错了会真的把杯子打碎。

第 2 节 机器看见 · OpenCV

人类用眼睛看世界，机器人用摄像头 + OpenCV。OpenCV 是一个开源的计算机视觉库——你把图片给它，它能找出颜色、形状、边缘。

🌼 怎么让机器"看见"一个红色的球？

不是教它"什么是红"——而是：把照片里每个像素的颜色值读出来，如果红色分量远大于绿色和蓝色，这个像素就是红的。把所有"红像素"圈出来，就是球的位置。

为什么用 HSV 而不是 RGB？

RGB：用红、绿、蓝三个数值表示颜色。问题是——光照一变，三个数值全变，很难设范围。

HSV：H色调（什么颜色）、S饱和度（多鲜艳）、V明度（多亮）。把"颜色"和"亮度"分开了！所以只要盯住 H，不管灯亮灯暗都能找到红色。

📄 颜色过滤的思路
# OpenCV 颜色过滤的核心思路

# 1. 读取图片（或打开摄像头）
# 2. 把 BGR 转成 HSV
# 3. 设定颜色的范围（例如红色）
# 4. 找出所有在范围内的像素

print("OpenCV 工作流程：")
print("图片 -> 转 HSV -> 设定颜色范围")
print("     -> 得到掩膜(白色=目标) -> 找到目标")
print("")
print("HSV 三要素：") 
print("  H 色调: 0度=红, 120度=绿, 240度=蓝")
print("  S 饱和度: 颜色纯度")
print("  V 明度: 亮度")

OpenCV 还能做什么？

  • 🔍 边缘检测：找出物体的轮廓（Canny 算法）
  • 📐 形状识别：判断是圆形还是方形（Hough 变换）
  • 👤 人脸检测：Haar 级联分类器
  • 🎯 目标跟踪：锁定一个物体并跟住它

第 3 节 机器学习入门

为什么机器人需要"学习"？因为真实世界太复杂，人手写规则永远写不完。机器学习就是让机器自己从数据里找规律。

🌼 让机械臂学会抓东西

传统编程：写"圆杯子用这种手势、方杯子用那种手势、软的轻一点、滑的紧一点……"——写不完。
机器学习：给机械臂看 10000 个成功和 10000 个失败的抓取例子，它自己学会怎么抓。

两种主流方法

监督学习：有标准答案的数据。告诉机器"这是猫、那是狗"。适合分类、预测。

强化学习：不给答案，只给奖励——做对加分、做错扣分。适合"走路、抓东西"这类没有唯一正确答案的任务。

📄 最简单的"学习"：找规律
# 最简机器学习：根据身高预测体重
# 思路：找一条直线 y = w*x + b 贴近所有数据点

身高 = [160, 165, 170, 175, 180]
体重 = [55, 60, 63, 70, 75]

# 假设已经"学"出了参数
w = 0.9
b = -88

def 预测(高):
    return w * 高 + b

for i in range(len(身高)):
    真实 = 体重[i]
    猜测 = round(预测(身高[i]), 1)
    print("身高", 身高[i], "真实体重", 真实, "预测", 猜测)

关键概念：训练 vs 推理

训练（Training）：拿着数据反复调整参数，很慢，可能要几小时几天。通常在部署前进行，也可能在新数据到来后重新训练。

推理（Inference）：参数固定后，拿新数据算结果，很快，几毫秒。天天用。

就像学开车（训练，慢）和开车上班（推理，快）。

第 4 节 机械臂 · 运动学

机械臂怎么知道手在哪？靠两个核心问题：

  • 正解（Forward Kinematics）：我知道每个关节转了多少度 → 算出末端手的位置
  • 逆解（Inverse Kinematics）：我想让手去某个位置 → 反推每个关节该转多少度
🌼 人手臂类比

正解：你闭着眼弯一下胳膊，大脑知道肩、肘各转了多少度，所以能"算"出手掌现在在哪。
逆解：你看见桌上有个杯子，大脑自动算出"肩转 20 度、肘弯 45 度"，才能把手伸到杯子那里。快到你感觉不到。

为什么逆解更难？

正解是唯一确定的：给定关节角度，手的位置只有一个答案。

逆解却可能有多个解：手要到这里，可以"肘朝上"也可以"肘朝下"；有时候还无解（目标太远够不到）。所以逆解需要挑一个最合理的解（通常选最省力、最不容易撞到自己的那个）。

📄 单连杆正解（最简）
# 一根连杆，长度为 L，转了角度 a
# 末端位置：x = L*cos(a), y = L*sin(a)

import math

L = 1.0
角度 = 45
弧度 = 角度 * math.pi / 180

x = L * math.cos(弧度)
y = L * math.sin(弧度)

print("连杆长", L, "米, 转了", 角度, "度")
print("末端位置: x =", round(x, 3), " y =", round(y, 3))
print("") 
# 试几个角度看看规律
for a in range(0, 91, 30):
    r = a * math.pi / 180
    print("角度", a, "度 -> x =", round(math.cos(r), 3), " y =", round(math.sin(r), 3))

多连杆：一个套一个

真实机械臂有好几根连杆。第二根的起点是第一根的终点，所以要把每一段算出的位置累加起来——这正是"坐标变换"要解决的问题（第 5 节）。

💡 URDF（Unified Robot Description Format）：一种描述机器人结构的文件格式。像写配置一样定义机械臂有几根连杆、关节怎么连，程序就能自动算正解/逆解。见 其他资料/urdf实战.docx 和 代码/urdf_learn.7z。

第 5 节 坐标变换

摄像头看到的"左边"和机械臂的"左边"不是一回事——因为它们的参考系不同。

🌼 你发微信告诉朋友"我在你左边"

如果你们面对面站着，你的"左"刚好是朋友的"右"！得先统一坐标系：以谁为原点、哪个方向是正方向。
机械臂同理——摄像头看到的杯子坐标，必须先"变换"到机械臂的坐标系里，机械臂才知道往哪伸。

两种基本变换

  • 平移：把原点挪一挪。比如从"以摄像头为原点"变成"以机械臂底座为原点"。
  • 旋转：把坐标轴转一转。比如摄像头 Z 轴朝前、机械臂 Z 轴朝上，需要转 90 度。
📄 坐标平移
# 摄像头看到杯子在 (30, 50)（以摄像头为原点）
# 摄像头装在机械臂底座前方 (100, 0)
# 杯子在机械臂坐标系 = 杯子坐标 + 摄像头偏移

杯子_摄像头 = [30, 50]
摄像头偏移 = [100, 0]

杯子_机械臂 = [
    杯子_摄像头[0] + 摄像头偏移[0],
    杯子_摄像头[1] + 摄像头偏移[1]
]

print("摄像头看到杯子在:", 杯子_摄像头)
print("摄像头装在底座前方:", 摄像头偏移)
print("杯子在机械臂坐标系下:", 杯子_机械臂)
📄 坐标旋转
# 把坐标轴逆时针转 90 度
# 旋转公式: 新x = -y,  新y = x

def 旋转90(p):
    return [-p[1], p[0]]

点 = [3, 1]
新点 = 旋转90(点)
print("原始:", 点, " 旋转90度后:", 新点)

# 转 4 次就回到原点，验证一下
p = [3, 1]
for i in range(4):
    p = 旋转90(p)
    print("转", (i+1)*90, "度:", p)
💡 核心思想：先平移、再旋转（或反过来，顺序很重要！），就能把任何坐标系里的点搬到另一个坐标系里。机械臂的运动学，本质就是一连串这样的变换。

第 6 节 控制稳定 · PID 调节器

想象开下坡的车：如果只知道"当前离目标差多远"，很容易刹车太猛、来回晃。PID 就是一个聪明的驾驶助手：

  • P（比例）：看"现在"误差多大 → 立刻用力修正
  • I（积分）：看"过去"误差累积 → 把一直存在的小偏差磨平
  • D（微分）：看"未来"误差变化趋势 → 提前刹车防抖动
公式 
输出 = Kp*误差 + Ki*累积误差 + Kd*(误差变化率)

公式不用背，记住"现在 / 过去 / 未来"三个词就够了。

📄 PID 核心逻辑（看它一步步逼近目标）
# PID 控制器
Kp = 0.5
Ki = 0.1
Kd = 0.2

目标 = 100
位置 = 0
累积 = 0
上次误差 = 0

for t in range(12):
    误差 = 目标 - 位置
    累积 = 累积 + 误差
    变化 = 误差 - 上次误差
    
    输出 = Kp*误差 + Ki*累积 + Kd*变化
    位置 = 位置 + 输出
    
    行 = "第" + str(t+1) + "步: 位置=" + str(round(位置,1))
    行 = 行 + " 误差=" + str(round(误差,1))
    print(行)
    上次误差 = 误差

print("") 
print("看！位置从 0 一步步逼近目标 100")

为什么三个都要有？

只有 P：会来回震荡，像新手开车一脚油门一脚刹车。

只有 P+I：不震了，但慢慢偏一点，回不来（比如一直往左飘）。

P+I+D：稳、准、快。D 会"预判"即将过冲，提前减速。

第 7 节 大脑 · 大模型本地部署

让机器会"想"，最常用的办法是给它接一个大模型当大脑。用 Ollama 就能在你自己电脑里跑一个，不用联网、数据不外传。

🌼 本地 vs 云端

云端大模型（如各种在线服务）：把问题发到别人的服务器，算完发回来。方便，但你的数据离开了你的电脑。
本地大模型（Ollama）：模型下载到你电脑上跑。慢一点、小一点，但数据完全不出门。

📄 调用本地大模型（Ollama）
# Ollama 本地大模型工作流程

print("1. 去 ollama.com 下载安装")
print("2. 命令行下载模型:")
print("   ollama pull qwen2:0.5b")
print("3. Python 调用:")
print("   import ollama")
print("   r = ollama.chat(model='qwen2:0.5b',")
print("     messages=[{'role':'user',")
print("       'content':'解释具身智能'}])")
print("   print(r['message']['content'])")
print("4. 模型在你电脑上跑，数据不外传")

大模型在机器人里干什么？

大模型不会直接控制电机。它的工作是理解你的意图，然后把任务拆成具体步骤。

你说："把桌上的杯子拿给我"
大模型想："这是一个抓取任务 → 需要先找到杯子 → 再规划路径 → 再执行抓取"
然后把指令交给下游的视觉模块和运动控制模块去执行。

第 8 节 耳朵嘴巴 · 听和说

光会「看」还不够，真正像人的机器人还得会听（ASR）和说（TTS）。这两个缩写拆开就懂了：

  • 🗣 ASR（Automatic Speech Recognition）：把人说的话，变成文字。
  • 🔊 TTS（Text To Speech）：把文字，变成人声播放出来。
🌼 天天都在用

你按住微信说话，它自动转成文字——这就是 ASR。
导航 App 把"前方 200 米右转"念出来——这就是 TTS。

📄 ASR + TTS 完整流程
print("一个完整的语音交互闭环：")
print("")
print("你说: 「帮我把水杯拿来」")
print("   | ASR 语音识别")
print("   v")
print("文字: 「帮我把水杯拿来」")
print("   | 大模型理解意图")
print("   v")
print("指令: 导航到水杯 -> 机械臂抓取")
print("   | TTS 语音合成")
print("   v")
print("机器人说: 「好的，正在拿水杯」")

为什么这两个常一起出现？

因为它们构成语音交互闭环：
用户说话 → ASR 转文字 → 大模型理解 → 生成回复 → TTS 转语音 → 用户听到。
少了任何一个，机器人都没法用"说话"跟你交流。

第 9 节 沟通 · 通讯与 MCP

机器人的各个"器官"需要互相说话：摄像头 → 大脑、大脑 → 电机、电机 → 大脑反馈。这就是通讯。

两种关键技术

WebSocket：双向实时对话，像打电话——两边可以随时发消息，不用等对方先问。适合需要"持续对话"的场景（机器人不断上报状态、不断接收指令）。

MCP（Model Context Protocol）：一套标准接口，让大模型能安全地调用外部工具和数据。比如"大模型，帮我查今天天气" → MCP 调用天气 API → 返回结果。

🌼 机器人内部的一次对话

大脑（大模型）→ 通过 MCP → 调用天气 API，得到"今天晴天"
大脑 → 通过 WebSocket → 告诉电机控制器，"晴天，去院子扫地"
电机 → 通过 WebSocket → 回大脑，"已到达院子，开始扫地"

第 10 节 机器怎么学习？

机器不是天生会做，它是"学"出来的。两种主流方法：

  • 🦜 模仿学习：看老师演示一遍，照着学。比如你亲手拖一遍机械臂，它记住动作再复现（课程里的 ALOHA 双臂机器人就是这么练的）。
  • 🎮 强化学习：做对了给奖励、做错了扣分，越练越聪明（像游戏 AI）。
打个比方

模仿学习 = "看老师写字，然后临摹"
强化学习 = "考试分高就奖、分低就罚，逼自己进步"

📄 两种学习方式的代码思路
# 模仿学习（Behavior Cloning）
print("=== 模仿学习 ===")
演示数据 = ["张开手", "靠近杯子", "合上", "抬起"]
for 步骤 in 演示数据:
    print("学习人类动作:", 步骤)
print("训练完成，可以复现了")
print("")
# 强化学习
print("=== 强化学习 ===")
总分 = 0
for 尝试 in range(5):
    得分 = (尝试 + 1) * 20
    总分 = 总分 + 得分
    print("第", 尝试+1, "次尝试, 得分:", 得分, " 累计:", 总分)
print("越练越聪明！")

为什么要两种都用？

模仿学习起步快——人类演示几十次，机器就能大致学会。但它只能学到演示过的动作，遇到新情况就懵。

强化学习能超越人类——自己试几万次，可能发现比人更优的动作。但试错成本高，在真机上可能摔坏设备。

所以常见做法：模仿学习打底 + 强化学习打磨。
